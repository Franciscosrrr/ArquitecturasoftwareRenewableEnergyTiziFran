# ADR-012 - D12 - Balanceo

Versión 1.0.0 · Entrega 2 · Estado: **Diseño propuesto; no implementado en este hito**. Autores: Tiziano Nicolas y Francisco Skrie. Reemplaza: ninguna.

## Contexto

El arranque de entrega 2 usa una instancia de cada servicio. El balanceo funcional sobre dos o más instancias se exige en la defensa final.

## Decisión

Mantener la propuesta de round-robin explícito en gateway hacia dos instancias Solar saludables. Chequeo cada 5 s, timeout 1 s, retiro tras dos fallos y reincorporación tras dos éxitos. Sin destinos: 503. Las réplicas Solar compartirán su propia MongoDB y usarán reclamo/lease e idempotencia para trabajo durable. No reintentar escrituras sin una garantía de idempotencia.

## Alternativas consideradas

Nginx/HAProxy simplifican operación pero ocultan parte de la decisión a defender; balancear Consumo stateless es posible, pero se eligió Solar por el procesamiento planeado. La decisión debe revalidarse cuando exista Solar real.

## Consecuencias y validación

En entrega 2 no se afirma distribución ni recuperación entre réplicas. La verificación futura debe registrar id de instancia y retirar una de ellas bajo tráfico. Una BD única seguirá siendo un punto de falla.

Las evidencias ejecutadas se enumeran en [DELIVERY-2](../DELIVERY-2.md). Una decisión propuesta no se presenta como una implementación validada.

# ADR-003-E2 - Persistencia inicial de catálogo y acceso SQL

Estado: adoptado y validado localmente. Reemplaza ADR-003 en lo relativo a la implementación inicial del catálogo; conserva el objetivo de BD por servicio para la final.

## Contexto

La entrega 2 requiere al menos un almacenamiento integrado al flujo. El visitante no debe guardar simulaciones. La propuesta inicial mencionaba GORM como biblioteca prevista, todavía sin código.

## Decisión

MySQL 8.4 para las fichas del catálogo Electrodomésticos. Volumen nombrado, usuario propio catalogo y secretos aleatorios locales. Tabla inicial y semillas por clave primaria; INSERT IGNORE transaccional conserva fichas existentes. Usar database/sql y go-sql-driver/mysql con consultas parametrizadas, timeouts y pool de 10 conexiones. Count/página leen el mismo snapshot.

## Alternativas

GORM es viable pero aporta mapeos/migración implícita innecesarios para esta lectura acotada; SQL explícito facilita revisar índices, orden y transacción. SQLite simplifica una demo, pero se aparta de la base ya propuesta. Guardar cálculos invitados para exhibir persistencia contradice el alcance; se persiste el catálogo que el cálculo consulta.

## Consecuencias y validación

Consumo no tiene credenciales de la base ajena. Integración real comprueba inicialización idempotente, búsqueda literal, parámetros, paginación e inactivos. La base es un único punto de falla y el esquema todavía necesita migraciones incrementales al evolucionar. Persistencia autenticada de Consumo/Usuarios y MongoDB de Solar siguen pendientes.

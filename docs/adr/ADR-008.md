# ADR-008 — Capacidad propia y contrato público versionado

Decisión del enunciado: D8. Versión: 1.0.0. Estado: **Adoptado y validado localmente en entrega 2; publicación cloud pendiente**. Reemplaza: ninguna. Autores: Tiziano Nicolas (2407889) y Francisco Skrie (2423159).

## Contexto

Otro grupo necesita una capacidad útil sin acceder a lugares privados ni acoplarse al catálogo interno. El TP pide contrato formal/versionado y ejemplos.

## Decisión

Consumo ofrece POST /api/v1/estimaciones-consumo: equipos por potencia/ciclo y hábitos, total/desglose/promedio. Operación sin efectos de negocio persistentes. Contrato OpenAPI 3.0.3 JSON, versión vigente 1.0.1 (versión inicial 1.0.0), credencial M2M X-API-Key, errores estables y límites explícitos.

## Alternativas consideradas

Publicar guardados personales expone privacidad y depende de identidad. Publicar solo paneles es una consulta CRUD menos reutilizable. Eventos podrían integrarse pero exigirían broker/conectividad al consumidor.

## Consecuencias y límites

El consumidor aporta fichas y hábitos y conoce los supuestos. La API no produce estudio Solar ni consulta lugares. Misma entrada/algoritmo determina igual energía; traceId es metadato variable. Cambios incompatibles requieren /v2. Los ejemplos acompañan un mock HTTP local ejecutable; sus credenciales y catálogo son simulados.

## Validación y evolución

Comparar respuesta real con contrato, casos inválidos y valores calculados; test consumidor. Publicar URL HTTPS gratuita y acordar cold start/cuotas antes de usarla en negocio. El mock local está implementado. La revisión de contrato 1.0.1 actualiza los metadatos documentales y la descripción del mock; conserva rutas, campos y fórmulas. El despliegue productivo sigue pendiente.

Si cambia esta decisión, conservar este ADR como reemplazado y crear otro con vínculo al anterior. Ver [arquitectura](../ARCHITECTURE.md) y [alcance](../../SPEC.md).

## Aclaración: acceso web sin cuenta

La capacidad M2M de este ADR mantiene su autenticación y versión. El modo invitado utiliza rutas propias sin JWT/API key y un contrato separado para evitar acoplar la web a credenciales de otro grupo. Ver [decisión complementaria](ADR-GUEST.md).

## Validación de entrega 2

El contrato M2M 1.0.1 se conserva sin cambios de rutas, campos, fórmulas ni unidades. Consumo Go reemplaza al mock en el arranque principal. Las pruebas HTTP reales verifican respuesta 200 de 47,4 kWh / 1,58 kWh/día y los errores de autenticación/validación. El contrato adicional de catálogo no reemplaza esta API externa. URL cloud todavía pendiente. TraceId W3C y X-Request-Id se correlacionan sin exigir igualdad; ver README del contrato para límites del parser.
